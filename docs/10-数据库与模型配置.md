# 数据库与模型配置

## 页面操作

登录后点击侧栏“数据库与模型设置”。每个账号可保存自己的 OpenAI 兼容模型地址、模型名、API Key 和超时，支持测试连接。地址填写接口前缀，例如 `https://provider.example/v1`，系统追加 `/chat/completions`。测试会调用一次模型并验证 QueryPlan，可能产生费用；保存操作不调用模型。设置在下一次查询生效。

管理员另可添加共享 MySQL 连接，读取该账号可见的库名、检查六张 ERP 表和必要字段，再保存连接。连接对全部登录用户可选；这不提供部门级或行级权限。只读账号权限应由 MySQL 管理员在数据库端设置。

侧栏“查询数据库”用于选择新会话的数据源。首次发送后会话固定绑定数据源，继续追问、刷新和重启均不会变更绑定；需要换库时先新建会话。连接当前为仅新增，修改凭据时添加新连接。旧会话没有绑定记录时使用服务器默认业务库。

当前使用既定的 `customers`、`salespeople`、`categories`、`products`、`orders`、`order_items` 表及原业务口径。添加连接不生成业务数据、不修改表结构，也不会自动适配任意命名的业务表。

## MySQL 部署

推荐应用库及业务库均使用 MySQL，模板为根目录 `.env.mysql.example`。应用库由 `APP_DATABASE_URL` 指定，保存账号、会话、快照、导出任务与连接配置；前端只切换业务库。未填写 MySQL 凭据时保留原 SQLite 演示模式。完整建库、账号授权和初始化步骤见 README 第 3 节。

现有应用升级时，API 自动补建 `runtime_settings`、`conversation_sources` 两张表，不修改业务库；应用账号需有 CREATE 权限。新应用库先执行 `manage.py seed --app-only` 初始化账号。已有 SQLite 数据不会自动转入 MySQL，切换应用库前需单独安排迁移。

## 接口与权限

| 接口 | 权限与作用 |
|---|---|
| `GET /api/settings` | 登录用户；返回可选数据库和本人的脱敏模型设置 |
| `POST /api/settings/databases/discover` | 管理员；使用填写的账号列出可见业务库 |
| `POST /api/settings/databases/test` | 管理员；检查连接及六表字段可读性 |
| `POST /api/settings/databases` | 管理员；检查通过后加密保存连接 |
| `PUT /api/settings/model` | 登录用户；保存本人模型设置 |
| `POST /api/settings/model/test` | 登录用户；测试填写的模型，不自动保存 |
| `POST /api/conversations` | 新增可选 `source_id`，默认 `default` |
| `GET /api/conversations/{id}` | 返回该会话绑定的 `source_id` |

写接口均要求当前会话的 CSRF Token。模型配置的归属由登录用户决定，不接受客户端指定用户 ID。API Key 不回显；同地址下留空保留原密钥，更换地址后必须重新输入，避免把旧密钥发送给新服务。数据库连接字符串也不返回浏览器。

密码和密钥用 Fernet 加密后存入应用库。加密密钥位于 `artifacts/config.key`，或由 `CONFIG_KEY_PATH` 指定；备份应用数据库时必须同时备份密钥。密钥丢失时拒绝解密与配置覆盖，需恢复原文件。Linux 密钥文件以 0600 权限创建；Windows 需通过部署目录 ACL 限制访问。
