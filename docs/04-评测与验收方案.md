# 04 评测与验收方案

> 本文定义未来测试方法；目前没有系统代码、真实测量值或已达标结论。
> “P95 ≤3 秒”是建议口径，须在 G0 获得确认。若验收要求每次均 ≤3 秒，应修改验收门槛并重新验证方案可行性。

## 1. 评测原则

1. 先冻结范围、口径、数据、题集和指标，再实现及验收。
2. 用查询语义和实际结果判断正确，不能仅对比 SQL 字符串或模型自评。
3. 不能因查询失败、超时或拒答就删题；不能用正确拒答冲高查询准确率。
4. 准确率和延迟必须在同一版本、同一查询路线下达标，禁止使用两个不同模式分别报喜。
5. 报告基于规定样本，不能推断为所有业务/所有数据库的准确率保证。

## 2. 数据集划分与防泄漏

| 集合 | 数量规划 | 用途 |
|---|---:|---|
| 提示示例与训练素材 | 80 题 | few-shot、口径规则、开发说明 |
| 开发验证集 | 120 题 | 选模型、提示词、编译器、边界与性能调优 |
| 正式查询盲测集 | 300 题 | 超过 90% 准确率的正式验收分母 |
| 歧义澄清集 | 60 题 | 缺时间、缺指标、重名实体、上下文歧义 |
| 安全与越界集 | 80 题 | 写操作、注入、越权、超复杂查询、未知指标 |

按问题结构、指标组合、关联路径和业务场景划分，不仅随机拆分同一句话的改写。盲测题不能进入提示词、缓存预置答案、示例库或调参日志。数据词典可公开，标准 SQL 和答案由验收人保管。

如果单人完成开发，应先冻结带版本摘要的验收集，明确记录访问情况；一旦使用某批题调参，须将其转入开发集并由独立方式补充新的盲测题，不能继续声称完全盲测。

### 2.1 300 题覆盖比例

| 主类别 | 题量 | 必含覆盖 |
|---|---:|---|
| 单表过滤与明细 | 60 | 组合条件、排序、空值、边界日期 |
| 单表聚合与分组 | 60 | 计数、金额、客单价、HAVING |
| 2～4 表关联 | 90 | 一对多去重、左右关联、按商品/类别统计 |
| 排名、占比、时间趋势 | 45 | Top N 稳定性、完整分母、缺月、零值 |
| 多轮明确追问 | 45 | 条件继承/替换、改时间、改地区、切换指标 |
| 合计 | 300 | 类别按主测试目标互斥归档 |

同一问题可带多个标签，但只计入一个主类别，避免重复计数。多轮题以完整会话为一个案例，要求每个被评估查询轮次均正确；性能测试则逐轮计时，并同时报告完整会话总时长。

### 2.2 每个案例必须保存

`case_id`、集合和难度、自然语言问题/上下文、冻结当前时间、时区、授权身份、数据快照版本、指标语义、标准查询或等价判定规则、结果类型、期望行/字段、排序规则、金额容差、图表映射、是否应澄清/拒绝。

标准答案来自独立编写并审阅的 MySQL 查询及微型数据手算；不得让被测模型生成自己的标准答案。重点案例用第二条等价计算路径交叉核对。

## 3. 正确性判定

### 3.1 一题通过的全部条件

- 正确识别指标、时间字段、区间、地区/实体及状态口径。
- SQL 符合授权、业务粒度和用户条件，没有结果偶然相同但语义错误的情况。
- 实际结果与标准结果等价；主键、数量、金额、排名及空值符合规则。
- 回答关键数字和单位全部来自正确结果；没有无依据的解释。
- 图表适用性正确；图表轴、序列、单位、顺序、占比分母与表格一致。
- 应展示全量统计时没有把分页/截断结果误作全量。

有序结果按标准次序比较；无顺序约束的结果按行多重集合比较，保留重复行语义，不能简单转成集合而掩盖重复。金额按 Decimal 比较；比率按预先规定的显示精度容差比较，不能临时扩大容差。

SQL 字面不同可以正确；SQL 字面接近但语义不同仍然错误。所有 300 题在基准及至少 2 个变体快照上执行；一题只有全部要求快照均通过才计为正确，以减少错误 JOIN 在单份数据上偶然命中的情况。

### 3.2 正式指标

| 指标 | 计算方式 | 通过线 |
|---|---|---|
| 查询端到端准确率 | 完整正确案例数 / 300 | ≥91%，至少 273 题 |
| 多表准确率 | 正确多表题数 / 90 | ≥90%，至少 81 题 |
| 单一主类别准确率 | 该类正确题 / 该类题数 | ≥85%，整数向上取整 |
| 澄清准确率 | 正确识别缺失信息且未擅自查数 / 60 | ≥95%，至少 57 题 |
| 危险 SQL/越权拦截 | 指定危险案例的成功拦截率 | 100%，任一危险执行即否决 |
| 超范围正确处理 | 给出明确范围说明、未伪造结果 | ≥95% |
| 回答事实一致性 | 成功回答与 SQL 结果数字一致 | 100%，发现事实篡改须修复 |

80 个安全/越界案例预分为 50 个危险/越权案例、30 个范围外案例。前者必须 50/50 拦截，后者至少 29/30 正确处理；范围外拒绝不纳入 300 题准确率。

明确问题的错误澄清、拒答、超时、无权限配置错误、上游错误都算该题失败；不存在“模型失败所以这题不计”的规则。

记录一次冻结完整运行作为正式结果，追加两次独立复测检验波动，三轮都应通过；不能只挑最好的一次。若有不同模型路由，将路由规则也冻结并共同计时，不允许测试时人工选模型。

报告建议附 Wilson 置信区间，说明有限样本的不确定性。273/300 的样本通过线不等价于“以 95% 置信度证明所有未来问题正确率超过 90%”；后者须另行提高样本量或通过标准。

## 4. 响应时间测试

### 4.1 计时起止

`T_complete = 浏览器完整结果可用时刻 - 浏览器点击发送时刻`。

完整可用要求：答案显示、首屏表格可读、适用图表完成渲染。不适用图表时以答案和表格完成为准。首 token、加载动画、HTTP 已接收均不是完成。

服务端另记录 `T_queue / T_context / T_llm / T_validate / T_db / T_analysis / T_snapshot`。客户端埋点用于端到端验收，不能只报服务器耗时。

### 4.2 环境与负载

建议基线为现代 4 核及以上 CPU、16 GB 内存、SSD，MySQL 与应用同机、浏览器同机、远程模型 API。它是准备条件而非性能担保；必须记录实际 CPU 型号、资源限额、操作系统、网络情况、模型版本与地域。

1. 固定 MySQL 版本、索引、数据快照、应用依赖、模型参数、提示词和语义目录。
2. 服务和连接池正常预热；预热请求不参与正式计数，次数提前固定，例如 20 次。
3. 分别执行 1 并发和 5 并发，每组至少 1,000 次完成尝试，问题混合比例与 300 题主类别一致；重复时关闭应用计划/结果缓存。
4. 记录实测吞吐、实际并发、错误率、P50/P90/P95/P99/最大值及慢请求明细。使用固定并发的闭环负载即可，但不能将其解释为任意到达率下的容量保证。
5. 缓存命中测试单独执行；供应商侧前缀缓存若无法关闭，记录相关 token/命中信息，不能声称模型服务完全冷缓存。
6. 冷启动另外测至少 20 次，公开启动耗时和首查询时延，不与预热结果混合。
7. 测一组查询与导出同时运行的干扰场景；若影响查询目标，限制导出并发或隔离资源。

### 4.3 性能通过线

- 在 1 并发及 5 并发下，**关闭应用计划/结果缓存**的范围内明确查询均满足完成时延 P95 ≤3 秒。
- 同时 `J = 正确且 T_complete ≤3 秒的尝试数 / 全部范围内明确查询尝试数 ≥90%`。
- 非预期服务错误率 ≤1%；超时、模型错误、数据库错误纳入错误率。
- 对于未生成完整结果的请求，不能把其快速报错耗时当作成功完成时延；计算完成时延分布时将其作为未完成并按无穷值排序，报告中同时提供其实际报错/截止耗时。
- 重试的原请求保留在分母；不能只测成功请求，也不能只拿缓存命中样本证明 3 秒。
- 单次 LLM 输出等阶段预算只用于定位问题；整体是否达标以以上端到端指标为准。

若不通过：定位模型、网络、数据库或渲染瓶颈后调整；无法兼顾时如实写“未达标”，并提出经批准的范围/资源变更，不能事后把完整响应改成首字响应。

## 5. 安全测试清单

- 多语句、大小写/空白/注释变形、版本注释、CTE/子查询中藏写操作或越权对象。
- `SLEEP`、`BENCHMARK`、文件读取/输出、锁操作、系统变量、系统库、跨库及笛卡尔积。
- 问题或表注释声称“忽略规则”“以管理员执行”，验证模型提示不能绕过安全网关。
- 交换用户的 conversation/result/export ID，验证读取、导出、下载均拒绝。
- 结果缓存及计划缓存不得跨用户权限泄漏；相对时间跨日不得复用错误日期。
- 数据库超时及客户端断开后，确认查询终止、连接不带异常事务归还、后续请求正常。
- 图表标题、客户名称和报告文字内的脚本/HTML 不执行；导出工作进程不访问任意 URL。
- 数据源管理不能成为普通用户任意连接目标的入口。

安全不以“模型一般不会这么生成”作为通过证据，必须直接对安全网关和接口构造输入测试。

## 6. 导出与交互验收

至少准备 20 组报告场景，各导出 Word 和 PDF 共 40 份，覆盖空结果、中文、宽表、跨页、1,000 行上限、金额精度、长标题、图表、截断提示及 SQL 附录。

- 文件可打开，关键文字、表格及图表齐全，中文无乱码，分页无严重裁切。
- 与原快照逐字段核对；导出期间变更业务数据也不得改变已保存结果。
- 快照过期、重复点击、生成失败、进程重启、无权下载均有正确处理。
- ≤100 行、≤2 图的小报告在固定环境下 P95 ≤10 秒；大报告遵守 60 秒截止并明确反馈，不伪称符合查询 3 秒。
- 主链路的发送、澄清、多轮、分页、改图、导出可由自动化浏览器重放；另人工检查文档版式。

## 7. 需求追踪与证据交付

| 用户要求 | 设计位置 | 关键验证证据 |
|---|---|---|
| MySQL 数据库 | 02 技术选择、03 数据模型 | 版本、建库记录、真实执行日志 |
| LLM 分析意图并自动生成 SQL | 02 查询链路 | 问题→计划→参数化 SQL→结果追踪 |
| 单表/多表 | 01 支持范围 | 各类别准确率、多表 90 题结果 |
| 自动回答/统计图表 | 01 指标、02 分析模块 | 数值对照、图表映射、页面截图 |
| 对话窗口展示 | 03 交互设计 | 浏览器端到端录像或测试报告 |
| Word/PDF | 03 导出流程 | 两种格式的样例和视觉检查记录 |
| 准确率 >90% | 本文第 3 节 | 冻结 300 题报告及失败列表 |
| 3 秒响应 | 本文第 4 节 | 客户端计时、负载、分位数及联合指标 |

未来评测报告需包含：版本与环境、题集摘要、各类分母、全量失败编号、缓存条件、准确率、延迟分布、联合指标、错误率、token/成本估算、未达标原因及复现步骤。当前所有实测字段均应填“待测”，禁止填入设计预算冒充测量值。
