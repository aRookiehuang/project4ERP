# 06 技术决策与参考依据

> 参考资料查阅日期：2026-10-14。以下官方资料用于验证基础能力；不构成本系统准确率或性能已达标的证据。

## 1. 决策记录

### ADR-01：固定业务域，而不是任意数据库即插即用

- 决策：首版只覆盖批准的 ERP 销售表与指标。
- 原因：SQL 语法无法自行解释“销售额”是否含退款、按下单还是付款时间；准确率首先依赖业务定义。
- 代价：迁移业务库需要语义映射和新评测集。
- 扩展条件：先证明当前域达标，再做数据源接入向导。

### ADR-02：LLM QueryPlan + SQL 编译优先

- 决策：LLM 理解问题并输出受控语义计划，服务端自动产生参数化 SQL；模型不能直接执行数据库工具。
- 原因：将不可预测的文本生成与可验证的查询算子分开，便于粒度校验、权限控制和延迟预算。
- 代价：首版 SQL 表达能力有限，开发需要一个小型编译层。
- 备选：模型直出受限 SQL，再经相同网关验证。仅在课程要求直接 Text-to-SQL 时启用并独立评测。
- 确认点：验收人是否要求“SQL 字符串本身必须由模型生成”。不能仅因名称为 Text-to-SQL 就声称两种路线完全相同。

### ADR-03：确定性事实摘要代替第二次模型润色

- 决策：摘要、排名、占比和趋势事实由已验证数据生成；LLM 用于理解自然语言。
- 原因：避免额外串行模型延迟、额外结果数据外发及数字幻觉。
- 代价：文字表达不如自由生成丰富，但首版更容易证明可信与快速。
- 扩展：可选异步润色需保留事实引用且单独标记完成时延，不能用未完成答案声称满足 3 秒。

### ADR-04：不用向量库、复杂 Agent 或模型微调作为首版前提

- 决策：6 表规模先用词典、关键词、实体索引和关系图召回。
- 原因：优先降低依赖、调用次数、调试难度与盲测泄漏风险。
- 扩展条件：schema 显著扩大且召回成为可测瓶颈，再加入向量检索；微调必须有独立数据和收益证据。

### ADR-05：完整响应验收，而不是首 token 验收

- 决策：以窗口中可使用的答案、表格和适用图表为完成标志。
- 原因：用户要的是查询结果，而非“已经开始处理”的提示。
- 待确认：采用 P95 是工程建议，不等同于用户自动接受了最坏时延放宽。
- 不能保证的事项：外部模型、网络和任意复杂 SQL 的每次绝对 3 秒上限。

### ADR-06：统一报告数据，分别生成 Word 与 PDF

- 决策：固定快照 → 统一报告数据 → python-docx / 打印 HTML 两种渲染器。
- 原因：不依赖 Office 自动化；数字一致；前端切页不影响导出数据完整性。
- 代价：需维护两份版式模板，必须做视觉回归。
- 不采用：浏览器截整页冒充可编辑 Word，或依赖客户端上传任意图片/HTML作为可信报告。

### ADR-07：只读账号只是底线，不是完整安全方案

- 决策：权限、AST、参数化、复杂度、超时、数据归属和导出隔离共同生效。
- 原因：只读 SELECT 仍可能访问不该看的表、调用危险函数或消耗大量资源。
- 代价：安全网关是核心模块，不能压缩为一条“禁止 DELETE”的正则。

## 2. 官方参考资料

| 来源 | 已核实的能力/限制 | 本项目使用方式 |
|---|---|---|
| [MySQL 8.4 参考手册](https://dev.mysql.com/doc/refman/8.4/en/) | 提供所选数据库版本的正式语法与运行配置说明 | 统一方言、版本及数据库行为依据 |
| [MySQL 优化器提示](https://dev.mysql.com/doc/refman/8.4/en/optimizer-hints.html) | `MAX_EXECUTION_TIME` 可为只读 SELECT 设置毫秒级执行时限，存在适用限制 | 结合驱动和请求截止控制；不能用它证明端到端 3 秒 |
| [MySQL 权限列表](https://dev.mysql.com/doc/refman/8.4/en/privileges-provided.html) | SELECT、FILE、EXECUTE 等权限分别定义 | 业务查询账户仅授予最小必需权限 |
| [SQLGlot 文档](https://sqlglot.com/) | 支持 SQL AST 分析与方言转换；解析器不等于严格引擎验证器 | 作为语法结构检查工具，叠加本项目安全与业务规则 |
| [千问结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output) | JSON Object 和 JSON Schema 约束程度不同，支持范围随模型变化 | 开工时确认具体模型能力，仍进行应用层业务校验 |
| [FastAPI Features](https://fastapi.tiangolo.com/features/) | 基于 Pydantic 的数据模型校验及接口文档能力 | 定义 API 与 QueryPlan 的类型契约 |
| [Vue Introduction](https://vuejs.org/guide/introduction.html) | 支持组件化构建交互界面 | 对话、表格、状态与页面组织 |
| [ECharts Dataset](https://echarts.apache.org/handbook/en/concepts/dataset/) | 数据集与图表配置可以分离 | 统一结果数据映射到受控图表 |
| [ECharts Server-Side Rendering](https://echarts.apache.org/handbook/en/how-to/cross-platform/server/) | 可输出适合静态文档场景的图形，交互能力有限 | 了解静态输出路线；首版选择无头浏览器固定图表 PNG |
| [python-docx Quickstart](https://python-docx.readthedocs.io/en/latest/user/quickstart.html) | 可创建段落、表格、插入图片并保存 DOCX | 生成可编辑报告正文与表格 |
| [Playwright Page PDF](https://playwright.dev/python/docs/api/class-page#page-pdf) | 页面 PDF 使用打印媒体样式，可设置页边距与页眉页脚 | 由本地可信模板生成 PDF |

第三方文档的可用能力不能替代项目实测：结构化输出不能保证指标正确；AST 能解析不等于 SQL 安全；数据库时限不等于完整响应时限；成功保存 DOCX/PDF 不等于报告版式合格。
