# 01 需求范围与业务口径

> 用户已确认首版采用 ERP 销售订单分析与模拟数据；具体表结构、数据规模和功能边界仍为规划方案。指标验收以 [04](04-评测与验收方案.md) 为准。

## 1. 用户与使用场景

- 查询用户：不熟悉 SQL 的业务人员或课程演示用户，查询本人有权访问的数据。
- 管理员：配置已批准的数据源、语义字典、示例问题和模型参数，查看脱敏审计记录。
- 首版采用预置演示账号和单一批准的数据源，不做注册、找回密码、任意用户自助连接数据库。
- 所有演示业务数据为模拟数据；不预置个人真实信息。

典型问题：

1. “2026 年 9 月销售额是多少？”——订单表聚合。
2. “列出 2026 年 9 月华东地区的已完成订单，按金额从高到低。”——过滤、排序、明细。
3. “2026 年各商品类别的月度销售额趋势。”——订单、明细、商品、类别 4 表关联。
4. “2026 年 9 月消费金额最高的 10 个客户是谁？”——订单与客户关联、分组、Top N。
5. “只看华东地区，改成折线图。”——继承上轮计划并修改条件/展现；图表不适用时说明。
6. “把这次结果导出成 Word。”——导出已有结果，不重新向业务库查询。

## 3. 明确的首版边界

### 3.1 支持

- 一次问题对应一个主要分析目标；明确的单个时间区间、最多 2 个分组维度、最多 3 个指标。
- `SELECT` 查询；等值、范围、集合、空值、受控的包含查询；布尔条件最多 8 个，嵌套最多 2 层。
- `COUNT / SUM / AVG / MIN / MAX`、排序、Top N、简单 `HAVING`。
- 已批准关联图上的 `INNER JOIN`、`LEFT JOIN`，最多 4 张不同业务表，不允许自关联。
- 按日/月分组；连续时间段补零仅用于可加总数量/金额指标，不能把缺失客单价补成 0。
- 上月、今年等常见时间表达；“最近 30 天”按请求日所在时区解释。
- 查询同一结果快照的分页；页面默认 20 行，最多保存和导出 1,000 行明细。
- 汇总查询至多 500 个完整分组；超过上限不展示被截断的“全局统计”，而是要求缩小范围。

### 3.2 暂不支持

- 业务数据新增、修改、删除、DDL、存储过程、文件读写、多语句与任意用户输入 SQL。
- 任意数据库零配置接入、跨库/跨数据源 JOIN、无限深子查询、递归 CTE、自由窗口函数。
- 退款净额、利润、成本、库存周转等缺少可靠基础数据与口径的指标。
- 因果归因、预测、自动经营决策；不能把相关性说成原因。
- 首版不做同比/环比；此类请求返回明确的范围说明，而非用错误日期近似。
- 超大结果全量导出、Excel 导出、上传任意文件做分析、完整 BI 拖拽报表设计器。
- 千万级实时分析、企业级多租户行级权限、分布式高可用、离线模型训练。

多意图问题例如“比较销售和库存，并预测明年需求”，应拆分或说明超范围。后续扩展必须增加数据字典、测试用例和性能复测，不能靠提示词无限扩大承诺。

## 4. 业务数据与指标口径

### 4.1 共用约定

- 时区：`Asia/Shanghai`；数据库业务时间使用已声明时区的 `DATETIME`，不隐式混用 UTC。
- 时间筛选采用左闭右开区间。例如 2026 年 9 月为 `[2026-09-01 00:00:00, 2026-10-01 00:00:00)`。
- 币种统一人民币；金额存储 `DECIMAL(18,2)`，内部十进制运算，展示保留 2 位小数。
- 有效销售订单状态：`PAID / SHIPPED / COMPLETED`；排除 `PENDING / CANCELLED`。
- 默认销售时间字段为 `paid_at`；问“下单数量/下单时间”时使用 `created_at`，不能替换。
- 每个订单仅对应一个客户、一名销售人员、一个销售地区快照；商品类别在首版数据集中不发生历史变更。
- 商品明细金额为已分摊优惠后的成交金额；订单金额等于其明细金额之和；不含运费、退款。
- “销售额/成交额/实付金额”映射到同一已登记指标；“净收入/利润”不映射。

### 4.2 指标目录

| 指标 | 定义 | 统计粒度与注意事项 |
|---|---|---|
| 销售额 | 有效订单的 `paid_amount` 之和 | 订单粒度；JOIN 明细后不得重复累加订单金额 |
| 商品/类别销售额 | 有效订单对应 `line_paid_amount` 之和 | 明细粒度；与订单销售额在全域汇总时应一致 |
| 成交订单数 | 有效订单的不同 `order_id` 数量 | 明细关联时使用去重订单数 |
| 下单数量 | 按 `created_at` 筛选的不同订单数 | 默认包括所有状态，明确标注与成交订单数不同 |
| 销量 | 有效订单明细 `quantity` 之和 | 单位为件，不是订单数 |
| 成交客户数 | 有效订单不同 `customer_id` 数量 | 不等于客户表记录数 |
| 客单价 | 销售额 / 成交订单数 | 订单口径；分母为 0 返回“无有效订单”，不生成无穷值 |
| 销售占比 | 某分组销售额 / 同一筛选范围全部分组销售额 | 分母不能使用截取后的 Top N；Top N 可显示“其他” |

按商品类别分组的“客单价”可能有多种定义，首版要求澄清或拒绝，不擅自应用订单级公式。客户/销售人员分组可使用订单级客单价。

### 4.3 聚合陷阱处理

- 订单和明细是一对多：统计订单额时优先在订单粒度聚合；按商品筛选订单总额时采用受控 `EXISTS` 过滤，不能直接 JOIN 后 `SUM(orders.paid_amount)`。
- 统计“购买商品 A 的客户消费金额”应澄清是该商品金额，还是包含该商品的整张订单金额。
- 人名/商品名可能重名：按 ID 聚合、名称展示；遇到同名实体选择时必须澄清。
- 无数据不等于执行失败；`SUM` 空集、零金额、缺失值必须区分。
- Top N 使用稳定次序：金额降序后按实体 ID 升序；默认精确 N 项，不自动扩展并列项。

## 5. 澄清与拒绝策略

| 情况 | 行为 |
|---|---|
| 没有指定时间的销售统计 | 询问时间范围，提供“本月/本年/全部数据”选项，不静默猜测 |
| 缺少年份但指定月份 | 要求确认年份 |
| “最近”“表现最好”含义不明 | 追问日期范围或评价指标 |
| 用户明确说“全部历史” | 使用该数据源全部可用时间范围，并显示边界 |
| 时间超出数据覆盖 | 正常返回无数据，说明数据覆盖，不偷偷改成有数据的月份 |
| 未知字段/指标/实体 | 解释缺失项，提供已支持项；不编造字段 |
| 越权、写操作、危险函数 | 拦截，不执行，不尝试自动修复绕过 |
| 模型/数据库超时 | 明确告知失败或重试入口，不返回猜测数字 |

澄清完成后，新请求携带原问题和确认条件；记录完整链路。明确问题被错误澄清，在准确率测试中算失败。

## 6. 分析与导出边界

- 自动摘要为事实性描述，例如总额、最高项、最低项、峰值月份；不生成没有数据支持的原因。
- 时间维度优先折线图，类别比较优先柱状图，非负金额且类别不超过 6 项时可用占比图。
- 图表默认最多 50 个可读点；更多点需经用户确认改粒度、Top N 或仅展示表格，不静默采样造成趋势失真。
- 单次导出只包含被选定的一条成功回答及其结果快照，不导出整个会话或重新查询最新数据。
- 明细最多 1,000 行，截断必须标注；不得将其称为全量结果。聚合统计必须来自完整合格查询，而不是对当前 20 行求和。
- 文档含问题、解释后的时间/口径、摘要、图表、表格、数据时间及查询追溯 ID；SQL 附录可选，默认隐藏敏感参数。
- Word/PDF 同一数据源，但不承诺像素级排版一致；都必须无乱码、无裁切、关键数据一致。
