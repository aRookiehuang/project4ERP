# 05 实施排期与风险管理

## 1. 工作原则

**先规划与确认，再编码；先证明最小查询链路，再扩展页面和报表；先验证正确性，再优化速度。**

本轮只生成这些 Markdown 文档。下述任务均为后续计划，不表示已经执行、已经安装依赖或已经产生测试结果。

## 2. 六周实施排期

按单人全职等效约 30 个工作日估算。实际截止时间和每日投入未确认，日数是规划估计，不是无条件工期承诺。

| 阶段 | 工作日 | 工作内容 | 交付物与门禁 |
|---|---|---|---|
| 规划确认 | 开发前 | 业务、技术栈、模拟数据和 API 路线已确认；继续确认 SQL 路线、范围及 3 秒口径 | 文档基线，G0；未确认不开始系统编码 |
| 第一周：数据与可行性 | D1～D5 | 冻结字典；准备微型/标准数据；模型适配；最小 QueryPlan→SQL→结果；20 个代表问题实测 | schema/口径、模型对比、窄闭环、安全初测、G1 |
| 第二周：可靠查询 | D6～D10 | 受控 SQL 编译器、AST 网关、只读执行、参数绑定、一对多口径、澄清和计时 | 单表/多表核心、开发集初测、安全回归 |
| 第三周：完整对话 | D11～D15 | 登录与会话、前端对话、答案/表格/图表、多轮、分页、结果快照 | 用户主路径可用，G2 |
| 第四周：导出与异常 | D16～D20 | Word/PDF、导出工作进程、中文字体、审计、取消/超时、错误状态 | 两种报告样例、端到端回放、G3 |
| 第五周：质量与性能 | D21～D25 | 开发集优化、索引/连接池、模型延迟对比、5 并发测试、资源干扰与安全复核 | 开发集 ≥95% 目标、性能候选报告、发布候选版本 |
| 第六周：盲测与交付 | D26～D30 | 冻结版本、正式验收、独立复测、缺陷缓冲、部署演练与答辩材料 | G4 报告、演示数据、部署/用户手册、最终交付 |

正式盲测暴露缺陷后若修改系统，须重跑全量相关测试；若已用盲测答案调参，按评测规程更换/补足新盲测题。不得为了赶进度将未达标项标记完成。

## 3. 关键工作包及依赖

### WP1：范围与数据（最高优先级）

- 已确认 ERP 销售订单 + 模拟数据；按该场景细化数据结构，不再等待已有库或真实数据。
- 确定 6 表、关联图、状态、时间及金额口径。
- 定义数据质量校验，准备微型手算用例及不同快照。
- 在开发前安排评测题集归属、冻结与保密方式。

完成条件：不写代码的人能凭文档计算一组标准答案。

### WP2：模型与编译链路（依赖 WP1）

- 对至少 2 个候选模型/配置使用同一开发问题测结构合法率、语义正确性、完整输出时延和 token 用量。
- 实现受限 QueryPlan、语义校验、JOIN 规划、SQL 编译、安全网关。
- 以“某月某地区客户销售额 Top 5”证明输入到真实结果的端到端闭环。
- 加入一对多重复累计、空结果、时间边界与提示注入测试。

G1 参考门槛：20 个代表问题至少 18 个端到端正确；含单表、2～4 表和歧义；取得至少 100 次真实调用的分段延迟。此小样本仅是可行性门槛，不能替代正式 300 题验收。

若模型阶段已长期超过总预算，先换模型/缩短计划/重新确认方案，不先把全部界面开发完再发现速度不可行。

### WP3：执行与安全（与 WP2 紧密衔接）

- 独立业务只读账号和应用写账号；登录与资源归属校验。
- 绑定参数、限制行数/字节、deadline、数据库时限、取消与连接清理。
- 确定性摘要、图表规则、结果快照、审计。

完成条件：数据库未授予写权限；所有危险执行案例均被阻止；正常结果可重放。

### WP4：对话与报告（依赖稳定结果契约）

- 按接口契约实现主页面及完整错误状态。
- 以同一快照实现表格分页、图表切换和导出。
- 报告中文字体、宽表跨页、打印样式、文件生命周期。

完成条件：不接触开发工具的用户可完成提问、追问、查看 SQL、下载两种文档。

### WP5：验收与交付（依赖以上全部）

- 版本冻结、盲测、性能、安全、导出视觉验证。
- 输出失败清单和实测报告，不只输出百分比。
- 从干净环境按手册部署，导入数据并复演。

关键路径为：**口径与数据 → 模型计划/SQL 编译 → 安全执行 → 结果快照 → 对话/导出 → 全量验收**。

## 4. 资源与成本规划

### 4.1 必要资源

- 一台具备 SSD、建议至少 16 GB 内存的开发机；本地小型演示不默认购买服务器。
- MySQL 8.4、Python/Node 运行时、浏览器及 Playwright Chromium；安装权限与空间在开工时检查。
- 大模型 API 可用账号、允许访问的 endpoint 和费用额度；由用户自行配置密钥。
- 可商用/可分发的中文字体；记录字体来源与许可证，不依赖开发机偶然已有的字体。
- 如果要求完全离线，先根据候选模型做显存/内存与速度测量，另出硬件方案，不能把本 API 方案原指标原样照搬。

### 4.2 成本估算方法

不在此引用可能变化的模型单价，也不预先购买资源。开发阶段计划约 5,000～10,000 次模型调用，具体依失败重试、快照复测和候选数量调整。

`模型费用 = Σ[(输入 token / 1,000,000 × 当期输入单价) + (输出 token / 1,000,000 × 当期输出单价)]`。

将开发实验、正式验收、性能压测分账；按供应商实际缓存计费规则核对。D1 记录所选模型当期价格，按用户批准额度设置日预算和告警；超过额度停止新实验并报告，不自动追加付费方案。

通过缩短上下文、限制输出和复用开发证据控制成本，不通过在盲测中预填答案节约调用。

## 5. 风险清单

| 风险 | 影响 | 预防与处置 |
|---|---|---|
| 外部模型完整输出超过 3 秒预算 | 性能不达标 | G1 实测；缩短输出、减少上下文、选择更快候选；仍失败则如实调整范围/资源 |
| LLM 生成业务口径错误但 SQL 可执行 | 准确率虚高 | 指标目录、受限计划、微型手算、变体快照和答案事实验证 |
| 多表一对多金额重复 | 大额统计错误 | 粒度检查、EXISTS/预聚合、专门回归用例 |
| 用首 token 或缓存冒充 3 秒 | 验收失真 | 浏览器完整渲染计时、关闭应用缓存、联合正确及时率 |
| 准确率只针对简单固定题 | 泛化不足 | 按模板族隔离、未见组合、多轮与多表分类门槛 |
| 真实库缺少字典或敏感信息外发 | 接入延期/数据风险 | 先映射脱敏；只发批准元数据，不默认上传业务结果 |
| 越权查询或导出泄漏 | 高风险安全缺陷 | 连接权限、AST、资源归属、缓存权限键与下载鉴权 |
| 导出占用查询资源 | 查询时延上升 | 独立工作进程、并发 1、同机干扰测试 |
| Word/PDF 中文乱码与裁切 | 功能看似完成但不可用 | 固定字体、实际渲染检查、宽表/跨页场景 |
| API 限流/不可用或版本变化 | 演示和结果不稳定 | 锁定模型配置、超时失败可见、备用配置独立复测 |
| 技术栈/业务范围后期变更 | 工期超出 | G0 确认；变更登记并重新估算，不隐式扩大首版 |
| 截止日期很近 | 质量缩水 | 减少非核心管理页面，不削减只读安全、准确性评测及两种导出 |

## 6. 变更管理

每次范围变更登记：提出原因、受影响的需求编号、数据/接口/测试变更、工期及指标影响、批准状态。增加同比、退款、库存、更多 JOIN 或真实库接入都属于范围变更，不是简单改提示词。

依赖升级、模型升级、语义目录升级会影响结果，必须保留旧版本配置和回归结果。可回滚版本包含代码、提示词、目录和数据库迁移，而不只是代码提交。
